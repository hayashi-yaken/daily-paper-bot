## 概要

GitHub Actions の `schedule:` で動かしている毎日 1 回の論文投稿が、Actions のスケジュール遅延（混雑時 30 分〜数時間）で実行が JST 11:30 頃に偏ってしまっている。論文の取得・整形・投稿処理自体は 1 分以内で終わっているため、遅延の原因はすべて GitHub 側のスケジュール待機に由来する。

これを解消するため、Google Apps Script（以下 GAS）の時間トリガーから GitHub の `workflow_dispatch` API を叩いて `daily.yml` を起動する構成に切り替える。GAS の時間トリガーは数分以内に発火するため、ボットの投稿時刻が JST 08:00 ぴったり付近に揃う。

既存の `schedule:` cron は撤去せず、起動時刻だけ JST 13:00 狙い（UTC 04:00）に後ろ倒しして、GAS が落ちた日でも遅延込みで午後には投稿が来るフォールバックとして残す。重複投稿防止機構は DPB-013 で廃止済みなので、GAS と cron の両方が動いた日は 1 日 2 投稿になる可能性があるが、運用上の許容範囲とする。

## 方針

- 遅延の原因は GitHub Actions のスケジュール仕様（best-effort）であり、`cron:` の文字列を調整しても根本解決にならない。**外部から `workflow_dispatch` を叩く以外に解決策はない**ことを前提に設計する。
- GAS を選んだ理由は (a) 完全無料・クレカ登録不要、(b) 個人 Google アカウントだけで完結、(c) 時間トリガーが JST 直指定でき精度が高い、(d) 必要なコードが 30 行程度で済むため。Cloudflare Workers / cron-job.org も技術的には可能だが、上記の総合点で GAS を採用する。
- このリポジトリは Go 製ボットの本体だが、GAS スクリプトはコピペ運用用の参照コードとして `scripts/gas/trigger.gs` に置く。`clasp` などの双方向同期はセットアップ工数が見合わないため導入しない。GAS 側の編集を行ったらリポジトリ側も手で更新するルールにする。
- 認証は **Fine-grained PAT**（このリポジトリ単独、`Actions: Read and write` のみ）を使う。Classic PAT はスコープが広すぎる、GitHub App は今回の用途に対して過剰、という理由で除外する。PAT は最大 1 年で期限切れになるため、期限切れ時の運用としては「GAS の失敗 → Slack 通知」で気付ける構成にしておく（Slack 通知のセクションを参照）。
- 既存の Actions `schedule:` は **削除せずに残し、起動時刻だけ JST 13:00 狙いに後ろ倒しする**。GAS が落ちた日（PAT 期限切れ・GAS 障害など）でも遅延込みで午後には投稿が来る状態を保ち、観測性を高める。重複防止は DPB-013 で廃止済みのため、GAS と cron の両方が動いた日は 1 日 2 投稿になりうるが、運用上の許容範囲とする。
- GAS からの失敗通知は **Slack Incoming Webhook** を使い、論文投稿と同じチャンネルに投げる。Bot Token + `chat.postMessage` ではなく Incoming Webhook を使う理由は、GAS 側に新たな Token を持たせず、最小権限（特定チャンネルへの投稿のみ）で完結させるため。失敗が目につくよう、専用チャンネルは作らず投稿先と同じチャンネルにする。
- GAS のリトライ・キャッシュは導入しない。1 日 1 回の単純な API 呼び出しのため、失敗時はその日の cron フォールバックに任せる。

## 方法

### 1. Fine-grained PAT の発行（ユーザー作業）

GitHub の **Settings → Developer settings → Personal access tokens → Fine-grained tokens** で以下の条件で発行する：

- Resource owner: `hayashi-yaken`
- Repository access: Only select repositories → `daily-paper-bot` のみ
- Repository permissions: `Actions` を `Read and write` に設定（他はすべて `No access`）
- Expiration: 任意（最大 1 年）。期限はカレンダー等に登録しておく
- 発行されたトークン文字列を控える（再表示不可）

### 2. Slack Incoming Webhook の発行（ユーザー作業）

既存の Slack App（論文投稿に使っているもの）に対して以下を実施する：

- Slack App の **Features → Incoming Webhooks** を有効化
- **Add New Webhook to Workspace** で投稿先チャンネル（論文投稿チャンネルと同じ）を選択して URL を発行
- 発行された Webhook URL を控える

### 3. GAS プロジェクト作成（ユーザー作業）

- `script.google.com` で新規プロジェクトを作成する
- リポジトリ `scripts/gas/trigger.gs` の内容を GAS エディタに貼り付ける
- **Project Settings → Script Properties** で以下を登録する：
  - `GITHUB_PAT`: 手順 1 で取得した PAT
  - `SLACK_WEBHOOK_URL`: 手順 2 で取得した Webhook URL
- **Triggers → Add Trigger** で以下を登録する：
  - 実行する関数: `trigger`
  - イベントのソース: 時間主導型
  - トリガーのタイプ: 日付ベースのタイマー
  - 時刻: 午前 8 時 〜 9 時（JST、`script.google.com` のタイムゾーンを Asia/Tokyo に設定しておく）

### 4. GAS スクリプトの実装方針

`scripts/gas/trigger.gs` の概略構造：

```js
function trigger() {
  const props = PropertiesService.getScriptProperties();
  const pat = props.getProperty('GITHUB_PAT');
  const webhookUrl = props.getProperty('SLACK_WEBHOOK_URL');

  const url = 'https://api.github.com/repos/hayashi-yaken/daily-paper-bot/actions/workflows/daily.yml/dispatches';
  const options = {
    method: 'post',
    contentType: 'application/json',
    headers: {
      Authorization: 'Bearer ' + pat,
      Accept: 'application/vnd.github+json',
      'X-GitHub-Api-Version': '2022-11-28',
    },
    payload: JSON.stringify({ ref: 'main' }),
    muteHttpExceptions: true,
  };

  try {
    const res = UrlFetchApp.fetch(url, options);
    const code = res.getResponseCode();
    if (code !== 204) {
      notifySlack(webhookUrl, `workflow_dispatch failed: HTTP ${code} ${res.getContentText().slice(0, 500)}`);
    }
  } catch (e) {
    notifySlack(webhookUrl, `workflow_dispatch threw: ${e && e.message ? e.message : String(e)}`);
  }
}

function notifySlack(webhookUrl, message) {
  // Webhook 投稿。失敗してもこれ以上できることがないので例外を握りつぶす
}
```

- スクリプト先頭にはセットアップ手順をコメントで記載する
- `muteHttpExceptions: true` で 4xx/5xx でも例外を投げさせず、ステータスコードで分岐する
- `notifySlack` は内部で `UrlFetchApp.fetch` を呼ぶ。Slack 通知自体が失敗した場合のリカバリは行わない（GAS の実行ログには残るため、最終手段はそちらで気付く）

### 5. `daily.yml` の修正

```yaml
on:
  workflow_dispatch:
  schedule:
    - cron: "0 4 * * *" # 毎日 04:00 UTC (JST 13:00) — フォールバック実行（プライマリは GAS からの workflow_dispatch）
```

`workflow_dispatch:` 側は既存のままで OK（追加実装なし）。

## 備考

- GAS の時間トリガーは「8:00〜9:00 の間で実行」のような時間帯指定のため、厳密に 08:00:00 ジャストには発火しない。実運用上は 08:00〜08:15 の幅で発火することを想定する。
- PAT は最大 1 年で期限切れになる。期限切れの兆候は「GAS が 401/403 を受けて Slack に通知 → その日は cron フォールバックで JST 13:00 以降に投稿が来る」という形で観測できる。
- GAS の 1 日のトリガー実行回数・`UrlFetchApp` の呼び出し回数は無料クォータ（1 日 20,000 回）に対して十分余裕がある。
- 重複投稿（GAS + cron の両方が動いた日）は DPB-013 の方針（重複防止廃止）と整合する想定上の挙動とする。
